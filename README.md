# 🌲 Лісова порадниця

Telegram-бот для мешканців лісу. Звірі надсилають документи з порадами, інші ставлять питання —
бот відповідає з урахуванням місця й завжди каже, з якого документа порада, хто й коли її надіслав.

## Швидкий старт

```bash
git clone https://github.com/menacerakuzan/forest-bot.git
cd forest-bot
cp .env.example .env   # вписати TELEGRAM_BOT_TOKEN і GROQ_API_KEY
docker compose up -d --build
```

Більше нічого не потрібно: «Лісовий архів» (78 документів) уже в образі, Tesseract для сканів —
теж. Docker Compose піднімає два сервіси: **PostgreSQL** і бота (бот стартує, щойно база готова).
Під час першого старту бот читає архів (~1 хв, разом з OCR сканів) і зберігає все в PostgreSQL
(том `pg-data`), тож наступні старти миттєві.

## Детальна інструкція

### 1. Що потрібно встановити

- **Docker** з Docker Compose v2: [Docker Desktop](https://www.docker.com/products/docker-desktop/)
  для macOS/Windows або Docker Engine для Linux. Перевірка: `docker compose version`.
- **Git** — щоб завантажити репозиторій (або скачайте ZIP на GitHub).

Python локально не потрібен — усе працює всередині контейнера.

### 2. Отримати токен Telegram-бота

1. Відкрийте [@BotFather](https://t.me/BotFather) у Telegram і надішліть `/newbot`.
2. Вкажіть назву (будь-яку — бот під час старту сам перейменується на «Лісова порадниця»)
   і username, що закінчується на `bot`.
3. BotFather надішле токен вигляду `123456789:AAE...` — це `TELEGRAM_BOT_TOKEN`.

### 3. Отримати ключ Groq

1. Зареєструйтеся на [console.groq.com](https://console.groq.com) (безкоштовно).
2. Розділ **API Keys** → **Create API Key**.
3. Скопіюйте ключ `gsk_...` — це `GROQ_API_KEY`. Платний план не потрібен.

### 4. Налаштувати `.env`

```bash
cp .env.example .env
```

Відкрийте `.env` і вставте обидва значення:

```dotenv
TELEGRAM_BOT_TOKEN=123456789:AAE...
GROQ_API_KEY=gsk_...
```

Решта змінних необов'язкові (див. таблицю нижче). Файл `.env` у git не потрапляє.

### 5. Запустити

```bash
docker compose up -d --build
docker compose logs -f bot
```

Бот готовий, коли в логах з'явиться `archive ready: 78 files` і `Run polling for bot @...`.
Відкрийте свого бота в Telegram і натисніть **Start**.

### 6. Що спробувати

| Що зробити | Чого очікувати |
|---|---|
| «Скільки внесок під дубом?» | 4 жолуді до 10 числа + джерело «Членські внески рукавички Під дубом» |
| «а під вербою?» | бот зрозуміє уточнення й назве внесок під вербою |
| «Коли йти по гриби під дубом?» | на 4–5 день після дощу: порада листяного лісу важливіша за загальну |
| «Як утеплити рукавичку під вербою?» | обидві поради (листяний ліс і річка) з поясненням, що вони розходяться |
| «Скільки треба платити?» | бот попросить уточнити місце й покаже кнопки рукавичок |
| «Скільки внесок під ялиною?» | 3 шишки — відповідь зі сканованого PDF |
| «Хто президент лісу?» | чесне «не знайшла» без вигадок |
| Надіслати `.txt`/`.pdf`/`.docx` з порадою | бот спитає ім'я (лише вперше), визначить місце або перепитає кнопками |
| Надіслати нову версію внесків під дубом | стара версія перестане діяти, у відповіді буде ваше ім'я й дата |
| `/my_docs` | список своїх документів з можливістю видалити |

### 7. Керування

```bash
docker compose logs -f bot        # логи
docker compose restart bot        # перезапуск
docker compose down               # зупинити (дані зберігаються в томі)
docker compose down -v            # зупинити й видалити всі дані (документи звірів теж)
git pull && docker compose up -d --build   # оновити до нової версії
```

### 8. Якщо щось не так

| Симптом | Причина й рішення |
|---|---|
| `встановіть TELEGRAM_BOT_TOKEN у .env` | не заповнено `.env` або він лежить не в корені проєкту |
| `TelegramConflictError` у логах | цей самий токен уже використовує інший запущений екземпляр — зупиніть його |
| `Unauthorized` / `401` | невірний токен бота або ключ Groq |
| Бот відповідає «у лісі зараз гамірно» | вичерпано ліміт безкоштовного Groq (8K токенів/хв, 200K/добу на модель) — зачекайте хвилину; бот сам перемикається на запасну модель |
| Довгий перший старт | OCR 19 сканованих PDF триває ~1 хв, далі старт миттєвий |

### Змінні оточення

| Змінна | Обов'язкова | За замовчуванням |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | так | — |
| `GROQ_API_KEY` | так | — |
| `GROQ_MODEL_ANSWER` | ні | `openai/gpt-oss-120b` — відповіді й класифікація документів |
| `GROQ_MODEL_FAST` | ні | `openai/gpt-oss-20b` — відбір доречних документів |
| `GROQ_MODEL_FALLBACK` | ні | `qwen/qwen3.8-27b` — коли основна модель упирається в ліміт |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | ні | `forest` / `forest` / `forest` — облікові дані бази в Compose |
| `TIMEZONE` | ні | `Europe/Kyiv` |
| `SETUP_BOT_PROFILE` | ні | `true` — бот сам ставить собі назву, опис і меню команд |

## Вимоги, з'ясовані з Мишкою

| Вимога | Як зроблено |
|---|---|
| Звірі надсилають поради документами: PDF, Word, текстові файли — від однієї поради до путівника | `.pdf`, `.docx`, `.txt`, `.md`; великі документи ріжуться на шматки, у відповідь іде найближче до питання |
| Звичайне текстове повідомлення — це завжди питання | будь-який текст іде у пошук відповіді |
| Надсилати може будь-який звір, усі рівні, модерації немає — порада одразу доступна | документ стає доступним одразу після збереження |
| 8 рукавичок; поради — для всього лісу, частини лісу або однієї рукавички | `places.py`: хвойний ліс, листяний ліс, біля річки; **Під вербою** належить і до листяного лісу, і до річки, **На узліссі** — ні до чого (як у «Карті лісу») |
| Документ — про один рівень; якщо з тексту незрозуміло, для кого він, — перепитати відправника, а не вгадувати й не ділити самому | LLM визначає рівень лише за явними ознаками; інакше бот питає автора кнопками «Весь ліс / частина / рукавичка». Якщо документ схожий на поради для кількох місць — теж питає автора (обрати одне місце або надіслати окремі документи) |
| Звір сам називає місце в питанні; якщо не назвав, а відповідь від нього залежить — уточнити | місце розпізнається в питанні (укр./рос., усі відмінки); без місця бот шукає серед порад для всього лісу, а якщо там немає — пропонує обрати місце кнопкою |
| Пріоритет: рукавичка → частина лісу → весь ліс; поради інших рукавичок не змішувати | до моделі потрапляють лише документи рівнів, що стосуються місця, упорядковані від конкретного до загального |
| Нова версія того самого документа для того самого місця замінює стару | LLM порівнює новий документ з наявними для того ж місця; стара версія вимикається, про це бот каже автору |
| У відповіді — з якого документа порада; для надісланих у Telegram — справжнє ім'я звіра й дата | джерела формує код (не LLM), тож вони завжди справжні; архівні документи — «назва — місце, Лісовий архів» |
| Справжнє ім'я питати, коли звір уперше надсилає документ (для питань не треба) | так; змінити ім'я — `/name` |
| Стандартні документи з теки «Лісовий архів» на Google Диску бот знає з самого початку | архів лежить у `data/archive` і вантажиться під час старту |
| Відповіді українською | так |
| Дві різні поради від різних звірів для того самого місця — це не нова версія, правило «брати новішу» не діє; обов'язково показати джерело кожної | **Моє рішення:** бот показує обидві поради й каже, хто що радить, з джерелом кожної |
| Бот працює лише в особистих повідомленнях, у спільні чати його не додають | обробляються лише приватні чати |
| Кнопка «Дякую» — «виріши сам»; головне, щоб було видно справжнє ім'я автора | **Моє рішення:** окремої кнопки немає — ім'я автора є під кожною відповіддю, тож дякують напряму |
| Сповіщення про небезпеки — «виріши сам» | **Моє рішення:** розсилки немає. Модерації немає, тож будь-який звір міг би розіслати тривогу всім; бот відповідає на питання про пожежі й мисливців, коли його питають |

**Рішення, які я запропонував і Мишка погодила:** назва «Лісова порадниця» та опис бота; для
Під вербою, коли поради листяного лісу й річки суперечать, — показати обидві й сказати про
розбіжність; кожен звір може переглянути й видалити свої документи (`/my_docs`), але не чужі
(після видалення нової версії знову діє попередня); якщо відповіді в документах немає — чесно
сказати «не знайшла», нічого не вигадуючи.

## Як це працює

```
документ ─► текст (pypdf / python-docx / OCR сканів) ─► LLM: назва, рівень, місце, опис
         ─► нова версія наявного? ─► PostgreSQL

питання ─► місце з тексту ─► документи лише застосовних рівнів
        ─► LLM обирає доречні за каталогом (+ документи тієї ж теми з інших рівнів)
        ─► LLM відповідає за документами з урахуванням пріоритету ─► відповідь + джерела
```

- **Скани.** 19 PDF в архіві — це картинки без текстового шару (зокрема внески чотирьох
  рукавичок). Такі PDF рендеряться й розпізнаються Tesseract (`ukr`) з бінаризацією фону;
  працює і для сканів, які надсилають звірі.
- **Ліміти безкоштовного Groq** (8K токенів/хв на модель). Тому в запит іде не весь архів,
  а каталог доречних документів, потім — лише обрані. Службовий крок і відповідь працюють на
  різних моделях (окремі ліміти), а при збої чи вичерпаному ліміті бот одразу переходить на
  запасну модель.
- **Структуровані відповіді.** JSON-режим Groq + перевірка pydantic. Строгий `json_schema` на
  gpt-oss у Groq нестабільний (порожні списки, «Failed to validate JSON»), тож від нього
  свідомо відмовився.
- **Метадані архіву** (рівень, місце, опис кожного файлу) закешовані в
  `data/archive_index.json` за хешем файлу, щоб не витрачати ліміти LLM на кожному старті.
  Нові файли в `data/archive` класифікуються автоматично; оновити індекс:
  `docker compose run --rm -v ./data:/app/data bot python -m forest_bot.build_index`.
- **Уточнення.** Бот пам'ятає кілька останніх питань звіра, тож «а під вербою?» після питання
  про внески працює. Відповіді бота в пам'ять не потрапляють — факти беруться лише з документів.
- **Безпека.** Тексти документів передаються моделі як дані, а не інструкції; відповіді
  екрануються перед відправкою; контейнер працює не від root.

## Розробка

Тести працюють зі справжнім PostgreSQL: кожен тест отримує окрему схему, яку потім видаляє.

```bash
uv sync
docker run -d --name forest-test-pg -p 127.0.0.1:54329:5432 \
  -e POSTGRES_USER=test -e POSTGRES_PASSWORD=test -e POSTGRES_DB=test postgres:17-alpine
export TEST_DATABASE_URL=postgresql://test:test@127.0.0.1:54329/test
uv run pytest          # 50 тестів; LLM підміняється фейком
uv run ruff check . && uv run ruff format --check . && uv run mypy src
```

```
src/forest_bot/
  places.py      географія лісу, рівні, пріоритети, розпізнавання місця в питанні
  extract.py     текст з PDF/DOCX/TXT, OCR сканів
  ingest.py      класифікація документів, заміна версій, завантаження архіву
  qa.py          відбір документів і відповідь з джерелами
  llm.py         обгортка Groq: JSON, валідація, запасна модель
  db.py          PostgreSQL (asyncpg, пул з'єднань)
  bot/           aiogram 3: обробники, клавіатури, тексти
```
